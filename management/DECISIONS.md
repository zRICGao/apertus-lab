## D011 — 2026-10-07：成对并行派发

按用户新要求，开发版允许在新实验规格中显式选择 `paired_parallel`，并固定最大在途请求数（偶数 2–8）。每批以 control/probe 为基本单位；预留全部成功后才派发，整批完成并写入证据后再进入下一批。错误、取消或超时阻止新批次，不能撤回已在途调用。默认仍串行，冻结发布包与历史账本不改；是否可提高真实吞吐需按 CSCS 服务约束验收。多 prompt 的自主生成仍依赖后续研究 Agent。

## D010 — 2026-10-07：研究 Agent 的角色与输出边界

研究 Agent 使用独立模型和凭据，只能检索、规划并提出结构化候选；唯一目标调用入口继续是受控 ExperimentManager/TargetClient。自动流程可产出证据支持的候选报告，不能自行把候选标记为已确认漏洞，也不能绕开冻结 replay、人工审核 Registry 或自动发布。先完成完整 Wiki 的来源/状态检索，再接 Planner；当前只落地禁用配置模板和只读预检。

## D008 — 2026-10-07：赞助计算下的文本 MVP
用户明确要求删除金额预算与精确定价控制，并选择三语言干扰示例。MVP 固定 CSCS 70B、文本、手工用例、串行、无重试/自主 Planner。保留调用额度、字符/输出上限、时限、取消和证据门控；不把精确输入 tokenizer 当启动条件，不宣称总 token 硬限制。

v2 live 模块与 v1 mock 契约分开，避免旧离线规范意外启用模型。每个 experiment id 的探索/确认阶段只可各运行一次；崩溃后封存不补发，明确新实验使用新 id。源代码和 spec 冻结后再独立 replay。金额相关旧门槛不再适用。

Wiki 是候选研究档案；人工 review registry 决定是否可导出。未知权重 revision 只能在有 scope_basis 的 hosted_service 范围确认，不能声称固定权重问题。官方 schema 仅做语法修复并保留原件与差异；上游认可未知。最终 PDF/提交必须有真实证据，不生成虚假发现。
