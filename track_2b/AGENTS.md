# Apertus Lab 工作约定

本项目用于搭建 BreachWeave 工作台、完整 LLM Wiki 应用，以及可复现的 Apertus 模型实验链路。

## 每次开始
1. 阅读 `HARNESS.md`、`PROJECT_OUTLINE.md` 和 `management/STATUS.md`。
2. 查看相关目录的现有文件与 Git 状态；保留用户已有修改。
3. 从状态表选择可执行的下一项，执行后记录证据、结果和下一步。

## 执行规则
- 以实际文件、命令输出和固定源码为依据，区分计划、已实现、已验证。
- 修改子仓库前阅读其 AGENTS.md；分别管理各组件的 Git 历史。
- 依赖、仓库来源和提交必须可追踪；不得因同名就替换 LLM Wiki 应用。
- 常规本地可逆工作可直接继续；缺少凭据、目标信息或关键选择时仅暂停依赖它的任务。
- 密钥不写入文档、日志、Git 或实验导出；示例仅放占位符。
- 研究 Agent 与被测 Apertus 分开配置。模型调用必须有明确目标、预算和证据记录。
- 不将一次异常、服务错误或语言混用直接标为确认发现。
- 本项目不默认授权第三方资产扫描、付费模型调用或外部发布。
- 完成一个工作单元后更新 STATUS、任务表及日志；验证失败也要记录。

本文件是项目内执行入口；具体管理流程见 HARNESS.md。
